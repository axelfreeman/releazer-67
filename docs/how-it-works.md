# How it works

## The insight

Your code already contains the marketing — it's inside the algorithms, the features, the logic. Most developers ignore it because digging it out is hard. Releazer extracts it automatically and turns it into a story a real person can understand.

## The pipeline

1. **Scan** — reads the traces: commits, PRs, diffs, changelog.
2. **Understand** — works out how the product *actually* works, not what the release claims. It reads the logic, not the marketing.
3. **Rewrite** — turns technical truth into human language: "what this means for you."
4. **Triage** — meaningful changes get a full launch; small ones accumulate quietly.
5. **Generate** — media pitches, social posts, ad campaigns, training videos, docs — in every format the release needs.
6. **Distribute** — sends the pitches, publishes the posts, launches the campaigns, updates the docs.
7. **Verify** — confirms each channel went out and logs what shipped.

## What "traces" means

The traces are what your coding agent already leaves behind, with no extra work from you:

- commits and PR titles/bodies
- diffs and changed files
- changelog and README edits
- release notes, if any

From that alone, Releazer reconstructs what shipped and why it matters.
